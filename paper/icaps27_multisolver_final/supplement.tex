\section{Models}

All engines receive one canonical instance (SHA-256 hashed) and identical start-time domains $[\ell_i, u_i]$: $\ell_i$ is the release plus job-predecessor work (or the committed start), $u_i = H - $ remaining job work, with $H$ the instance horizon. Three formulations are used. \textbf{Interval models} (CP-SAT, CP Optimizer): one interval per operation, job precedences, one no-overlap constraint per machine containing fixed outage intervals. \textbf{MiniZinc} (Gecode, Chuffed): integer starts with a \texttt{disjunctive} constraint per machine over operations and outage blocks. \textbf{Disjunctive MILP} (Gurobi, CPLEX, SCIP, HiGHS, CBC, GLPK), built once and translated verbatim:
\begin{align*}
& s_j - s_i - M_{ij} y_{ij} \ge p_i - M_{ij}, \quad s_i - s_j + M_{ji} y_{ij} \ge p_j && \text{for ops } i<j \text{ on one machine},\\
& M_{ij} = u_i + p_i - \ell_j, \quad M_{ji} = u_j + p_j - \ell_i, && C \ge s_i + p_i,\ \min C,
\end{align*}
where pairs whose order is implied by the bounds receive no binary, and an outage $[a,b)$ gets a binary only if the operation can lie on either side. Each big-M is the smallest constant that leaves every schedule within the bounds feasible. Restricted neighbourhoods add the same rows to every formulation: $C \le U-1$ and $s_v \ge s_u + p_u$ for each kept machine arc $(u,v)$. \texttt{tests/multisolver/test\_equivalence.py} (183 tests) checks every engine against an exhaustive enumeration optimum on 16 instances covering all constraint features, INFEASIBLE exactly when the cutoff is below the optimum, kept-arc enforcement, and that no MILP row cuts an oracle-optimal schedule. Model sizes and construction times are in Figure~\ref{fig:s6} and Table~\ref{tab:s4}.

\section{Methods and what differs between engines}

S0 cold; S1 solver-native warm start from the repaired previous schedule; S2 the same schedule retained outside the solver, then a cold solve; S3 full incumbent portfolio, then a global stage hinted where the engine supports it; S4 S3's portfolio, the selective stage and up to nine critical-region rounds ($C\le U-1$, kept arcs) on the same engine, then the global stage; S5 (CP-SAT only) S3 with CP-SAT's interleaved native LNS. \emph{Initialization is not uniform}: Gecode, Chuffed and GLPK accept no warm start (S1 not run; their S3/S4 global stages are cold solves with the incumbent retained externally); restricted rounds are hinted only for CP-SAT and CP Optimizer; CBC and GLPK report only final solutions. Restricted rounds therefore test the \emph{pipeline} on each engine, not identical search.

\section{Protocol}

Frozen plan (\texttt{results/multisolver/FROZEN\_PLAN.json}, hash in \texttt{FROZEN\_PLAN.sha256}) written before any held-out run, with each engine's Experiment~C configuration chosen on development streams only. Tiers: 8$\times$6 (10 held-out streams), 15$\times$15 and 20$\times$20 (5 held-out streams each), 10 disruption steps per stream. $B=8$\,s, one worker, one fresh interpreter per run pinned to a dedicated performance core; S0 of stochastic engines is run with 5 seeds. Exploratory: $B=2$\,s and $B=30$\,s, four workers. Unit of inference: the stream. Statistics: exact two-sided sign test on stream means, Holm correction within each family, 10{,}000-resample stream bootstrap CI of the mean paired difference scaled by the comparator mean (the same convention as the CP-SAT study, so intervals can extend below $-100\%$); significant = Holm $p<0.05$ and CI excluding zero. With five streams the smallest attainable two-sided sign-test $p$ is $0.0625$: paper-scale comparisons cannot reach significance under the frozen rule and are reported descriptively.

\paragraph{Host contention.} The host was shared with an unrelated CPU-bound workload that we neither started nor stopped (median 1-minute load average \MSLoadAvg{} on 20 logical CPUs). Every run records its CPU/wall ratio; the median for single-worker runs is \MSCpuWall{} and \MSCpuWallLowPct\% of them fall below $0.8$. The pre-declared sensitivity analysis repeats every comparison on runs with CPU/wall $\ge 0.8$: \MSSensChanged{} of \MSSensTotal{} significance decisions change (\texttt{analysis/heldout\_cpu08.json}).
