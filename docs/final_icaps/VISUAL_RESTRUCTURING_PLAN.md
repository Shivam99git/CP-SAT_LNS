## Deliberately NOT separately visualized

- **Figure 2 (Gantt worked example):** explicitly deferred to supplement per the task's own fallback instruction ("if space is insufficient, move to supplement rather than sacrificing main findings") — main-text space is prioritized for data-backed figures per the explicit priority order (architecture > main anytime > critical-vs-timewindow > main statistical comparison > worker/budget robustness), and this item is illustrative, not experimental, so it ranks below all five.
- **A separate "disruption-specific performance" figure (old Figure 7):** merged into the robustness heatmap (item 4) rather than given its own figure, because U6/U7/U8 (disruption-specific settings) and U3/U4/U5 (worker/budget settings) are statistically identical in kind (each is one more confirmatory setting compared the same way against the same two baselines) — splitting them into two figures would repeat the same visual grammar for no added information, which the task's own "avoid charts merely to repeat information" principle warns against.
- **A separate ablation table for "which pipeline component matters" (ablations A5/A7/A9):** these are *development-phase* (exploratory) ablations from the prior stage (`docs/unified_icaps/03_lns_baseline_protocol.md` §6), not part of the frozen confirmatory family. They are mentioned in one sentence with a pointer to supplementary material, not given main-text table/figure space, to avoid mixing confirmatory and exploratory evidence in a way a reader could mistake for equally strong.
- **A separate algorithm-pseudocode box in addition to the architecture diagram:** the existing Method section's four-step prose description (recompute chains -> build N -> solve restricted -> accept iff improving) is already essentially pseudocode-length; formatting it as an `algorithm` environment (already loaded via `\usepackage{algorithm,algorithmic}`) replaces that paragraph directly, counted under item 5's table but implemented as a compact algorithm box, not a separate narrative addition.
